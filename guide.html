HEALS 場域研究 · 操作手冊

遠端遙控 → 連續收集 → 自動回傳 → 心率路線圖。一份從頭到尾的操作流程。

一、系統由哪幾塊組成

四個角色,各司其職:

  • 控制面板（網頁）psycho-physiology.healsdesign.org　研究主持人按「開始／停止」下指令、看各專案狀態。
  • 後端（Netlify 函式 + Blobs）　記住每個專案的指令、收各裝置上傳的資料。看不到、不用管,自動運作。
  • HealthProbe（iPhone App，搭配 Apple Watch）　受測者裝置：輪詢後端、自動開始記錄、把資料上傳。
  • 資料主控台 console（網頁）…/console.html　把後端的資料抓回來，出地圖與 Excel。

資料流：面板按開始 → 後端記指令 → 手機輪詢到、自動清空＋開軌跡＋開基線 →（走測＋手錶運動）→ 面板按停止 → 手機上傳 → console 抓取出圖。

二、一次性設定（每台裝置做一次就好）

目的讓每台受測裝置認得後端、知道自己是哪一號。
操作HealthProbe →「工具」→「遠端總開關」，填三格並保存：
欄位填什麼說明
後端網址https://psycho-physiology.healsdesign.org所有裝置都一樣。結尾有沒有 / 都行。
專案名稱例：aa、大安森林A必須和面板上那個專案一字不差（含大小寫、空格）。
本機編號例：#1、#2一組「Apple Watch ＋ iPhone」＝一個編號＝一位受測者。多人時各填各的。
多受測者：每台手機填「同一個專案名 ＋ 自己的編號」，就會一起聽同一個開關，各自上傳到同一個專案底下。

三、單場走測流程

分五個階段。每步都標了「目的」與「操作」。

階段 A · 開始前（在起點、室外開闊處）
1打開控制面板、選好專案
目的準備好要下指令的專案。
操作手機或電腦開面板 → 若沒有該專案，於「新增專案」輸入名稱後「加入」。
2受測者手機：開好遠端總開關
目的讓手機開始持續詢問後端「研究開始了沒」。
操作HealthProbe →「工具」→「遠端總開關」→ 確認三格設定無誤 → 打開「自動輪詢（每 20 秒）」。
3Apple Watch：開始「戶外步行」運動
目的關鍵步驟。只有在運動進行中，手錶才會密集量心率（約每 5 秒一次）；平時背景量得很稀疏，畫不出沿路漸層。
操作手錶 → 體能訓練 →「戶外步行」→ 開始。
4面板：對該專案按「開始」
目的正式下達「研究開始」指令，後端會給這一場一個專屬場次號。
操作面板上找到專案 → 按綠色「開始」→ 狀態變「研究中」。
5回手機確認已開始記錄
目的確定手機真的收到指令、開始記錄。
操作切回 HealthProbe 的遠端總開關頁（讓它在前景）→ 20 秒內、或按「立即檢查一次」→ 應看到：
　• 專案狀態 →「研究中」（綠）
　• 本機動作 →「✅ 已開始本場記錄：清空軌跡＋開軌跡＋開基線」
　• 第一次會問定位權限 → 選「永遠允許」
　• 螢幕最上方出現藍色定位列（＝背景定位記錄中）
階段 B · 走測
6沿規劃路線走
目的同時收集心率（手錶）、GPS 軌跡（手機）、環境（自動）。
操作可鎖屏，走 5–10 分鐘、數百公尺，盡量在開闊天空下（室內 GPS 會飄）。手錶運動全程別停。
階段 C · 結束
7面板：按「停止」
目的結束這一場、記下停止時間。
操作面板對該專案按「停止」→ 狀態變「已停止」。
8回手機確認已停止
目的確定軌跡記錄已收。
操作HealthProbe 遠端總開關 → 按「立即檢查一次」→ 本機動作顯示「■ 已停止本場軌跡記錄」、藍色定位列消失。
9Apple Watch：結束運動
目的結束體能訓練、停止密集量測。
操作手錶上結束「戶外步行」。
階段 D · 同步 ＋ 撈取（最關鍵、最容易漏）
10讓手錶把心率同步到手機
目的手錶的心率不是即時傳到手機的，要先同步過去，手機才撈得到。
操作把 Apple Watch 放上充電座（最可靠、最快的同步觸發）→ 等 3–5 分鐘。不充電也會慢慢同步，只是較久且不固定；詳見下方說明。
11App 撈取生理
目的把同步好的心率，收進 App 的生理資料流。
操作HealthProbe → 撈取生理那頁 → 按「撈取」→ 看「本次新增」數字跳上來（這趟的心率到了）。沒跳就再等一下、再撈一次。
階段 E · 上傳 ＋ 出圖
12上傳本場資料
目的把這一場的 生理＋軌跡＋環境 一次送到後端。
操作HealthProbe 遠端總開關 →「上傳本場資料」→ 顯示「✅ 已上傳本場：生理 N・軌跡 M・環境 K」。生理偏少？充電同步 → 撈取 → 再按一次上傳即可更新（後端同 key 覆蓋）。
13console 抓取，出地圖與 Excel
目的把後端資料抓回來，產生視覺化與報表。
操作開 …/console.html → 後端專案名填同一個（如 aa）→ 按「從後端抓取」→ 卡片列出每位（編號×場次）→ 地圖畫出路線 → 「產出專案 Excel」下載報表。
14把地圖變成心率漸層
目的看出路線上哪段心率較高／較低。
操作console 左側「地圖上色方式」切到「依數值」→ 指標選 heart_rate → 點會依心率冷→暖著色。也可調「時間容差」「GPS 精度上限」「資料點大小」。

四、為什麼要「充電同步」？

Apple Watch 量到的健康資料，是有空才同步到 iPhone，不是即時的。放上充電座時手錶會跑背景同步，所以最穩、最快。

不充電資料還是會到，只是慢且不固定（幾分鐘～幾十分鐘）。想加快但不充電：手錶戴著、手機放旁邊、兩台短暫亮屏，或打開 iPhone「健康」App——但都沒有充電穩。

正式研究實務：別要求每位受測者走完馬上充電（不切實際）。改成等自然同步後再上傳；上傳可重按覆蓋，所以先上傳一次、之後資料陸續同步進來再按一次補齊即可。

五、欄位設定速查

地方欄位要點
HealthProbe 遠端總開關後端網址所有裝置相同：https://psycho-physiology.healsdesign.org
HealthProbe 遠端總開關專案名稱與面板一致（一字不差）
HealthProbe 遠端總開關本機編號每台不同，如 #1、#2
控制面板後端網址掛在站上會自動帶；本機開則填上面那個網址
控制面板專案新增後按「開始／停止」
console後端專案名填要檢視的專案（與面板一致）

六、常見狀況

狀況原因 / 處理
上傳後生理筆數很少手錶還沒同步完。充電同步 → 撈取 → 再按一次「上傳本場資料」（覆蓋更新）。
console 地圖沒畫出來該位需同時有「生理」與「軌跡」才畫得出沿路心率。只有環境或只有軌跡不會畫。
「立即檢查一次」按了沒變化狀態本來就是當前值（如已是「研究中」），屬正常。自動輪詢每 20 秒會自己更新。
抓回來是舊資料console 已設不讀快取；若仍懷疑，網址列開 …/api/data?project=你的專案&t=任意數 看後端原始內容。
心率稀疏、路線著色很空走測時忘了開 Apple Watch「戶外步行」運動。下次務必先開運動。
定位「永遠允許」沒設到設定 → HealthProbe → 位置 → 改成「永遠」（背景記錄需要）。

七、資料格式（給接手者參考）

三條流以 ISO8601 時間編碼；console／對接工具皆認得這套 schema。

生理 physiology { hkUUID, metricType, time, value, unit, sourceDevice }

metricType：heart_rate、resting_heart_rate、respiratory_rate、hrv_sdnn、vo2max、wrist_temp、spo2、audio_exposure_db

軌跡 location { id, time, lat, lng, accuracyM }

環境 environment { id, time, snapshot{ airTempC, apparentTempC, humidityPct, usAqi, pm25, pm10, no2, ozone, windSpeedMs, weatherDesc, latitude, longitude, … } }

後端每個場次存成一筆：{ project, code, session, uploadedAt, counts, physiology[], location[], environment[] }。
